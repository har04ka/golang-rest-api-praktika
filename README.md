# REST API — таск-трекер

Бэкенд на Go для управления задачами с аутентификацией, ролевой моделью и разграничением доступа. Пользователи видят только назначенные им задачи; администраторы управляют задачами, пользователями и назначениями.

## Стек

- **Go** — роутер [chi](https://github.com/go-chi/chi)
- **PostgreSQL** — драйвер и пул соединений [pgx](https://github.com/jackc/pgx)
- **Аутентификация на сессионных токенах** — поддержка Bearer-токена (для мобильных клиентов) и HttpOnly-куки (для веба)
- **bcrypt** для хеширования паролей, **HMAC-SHA256** для подписи токенов сессий
- **Ролевая модель** (обычный пользователь / администратор) с разграничением через middleware
- **Graceful shutdown** по сигналам ОС
- Конфигурация через переменные окружения ([godotenv](https://github.com/joho/godotenv))

## Запуск

### Через Docker (рекомендуется)

Нужен установленный Docker. Всё поднимается одной командой — приложение и PostgreSQL.

1. Скопировать `.env.example` в `.env`:

```bash
cp .env.example .env
```

Значения по умолчанию уже подходят для запуска в Docker. Важно: в `DB_URL` хост должен быть `db` (имя сервиса базы в `docker-compose.yml`), а не `localhost`:

```env
PORT=:8080
SECRET_KEY=случайный_hex_ключ
DB_URL=postgresql://postgres:postgres@db:5432/postgres
ADMIN_LOGIN=admin
ADMIN_PASSWORD=задай_надёжный_пароль
```

2. Поднять проект:

```bash
docker compose up --build
```

Приложение соберётся (multi-stage сборка Go), PostgreSQL поднимется, схема из `schema.sql` применится автоматически при первом запуске, и сервер стартует на `http://localhost:8080`. Приложение дожидается готовности базы через healthcheck, поэтому порядок запуска контролировать не нужно.

Остановить и удалить контейнеры вместе с данными базы:

```bash
docker compose down -v
```

### Локально (без Docker)

1. Поднять PostgreSQL и применить схему:

```bash
docker run --name taskdb -e POSTGRES_PASSWORD=postgres -p 5432:5432 -d postgres:17-alpine
docker exec -i taskdb psql -U postgres -d postgres < schema.sql
```

2. Скопировать `.env.example` в `.env`. Для локального запуска хост в `DB_URL` — `localhost`:

```env
DB_URL=postgresql://postgres:postgres@localhost:5432/postgres
```

3. Запустить приложение:

```bash
go run ./cmd
```

Сервер стартует на `http://localhost:8080` (порт берётся из `PORT`).

### Первый администратор

Публичной регистрации в API нет: создавать пользователей может только администратор (эндпоинт `POST /users` помечен 👑). Чтобы было кем войти в свежую базу, первый администратор **создаётся автоматически при первом запуске** — из переменных `ADMIN_LOGIN` и `ADMIN_PASSWORD`. Пароль хешируется (bcrypt) перед сохранением.

Сидинг идемпотентен: если администратор в базе уже есть, при следующих запусках ничего не создаётся и не дублируется. Если `ADMIN_LOGIN` или `ADMIN_PASSWORD` не заданы, приложение завершится с ошибкой при старте.

После запуска можно залогиниться кредами админа через `POST /auth/login` и пользоваться API.

## Аутентификация

После логина сервер возвращает токен сессии и одновременно ставит его в HttpOnly-куку `session_token`. Для защищённых эндпоинтов клиент передаёт токен одним из способов:

- в куке `session_token` (веб-клиент — автоматически);
- в заголовке `Authorization: Bearer <token>` (мобильный клиент).

## Эндпоинты

Обозначения: **🔓** — открытый, **🔒** — требует аутентификации, **👑** — только для администратора.

### Служебные

| Метод | Путь | Доступ | Описание                |
| ----- | ---- | ------ | ----------------------- |
| GET   | `/`  | 🔓     | Корневой ответ-заглушка |

### Аутентификация

| Метод | Путь           | Доступ | Описание                                              |
| ----- | -------------- | ------ | ----------------------------------------------------- |
| POST  | `/auth/login`  | 🔓     | Логин по логину и паролю, выдача токена сессии и куки |
| POST  | `/auth/logout` | 🔓     | Удаление сессии (по Bearer-токену или куке)           |
| GET   | `/auth/me`     | 🔒     | Профиль текущего пользователя                         |

### Пользователи

| Метод | Путь                  | Доступ | Описание                                           |
| ----- | --------------------- | ------ | -------------------------------------------------- |
| GET   | `/users`              | 🔒     | Список пользователей (публичные поля)              |
| GET   | `/users/{id}`         | 🔒     | Публичные данные пользователя по id                |
| GET   | `/users/me/completed` | 🔒     | Количество выполненных задач текущего пользователя |
| POST  | `/users`              | 👑     | Создание пользователя                              |

### Задачи

| Метод  | Путь                   | Доступ | Описание                                                     |
| ------ | ---------------------- | ------ | ------------------------------------------------------------ |
| GET    | `/tasks`               | 🔒     | Список задач (свои — для пользователя, все — для админа)     |
| POST   | `/tasks/{id}/complete` | 🔒     | Переключить статус выполнения задачи (нужен доступ к задаче) |
| POST   | `/tasks`               | 👑     | Создать задачу                                               |
| GET    | `/tasks/{id}`          | 👑     | Задача с назначенными пользователями                         |
| PATCH  | `/tasks/{id}`          | 👑     | Обновить задачу                                              |
| DELETE | `/tasks/{id}`          | 👑     | Удалить задачу                                               |
| POST   | `/tasks/{id}/users`    | 👑     | Назначить пользователей на задачу                            |

## Структура проекта

```
.
├── cmd/                 # точка входа, запуск сервера, graceful shutdown
├── config/              # загрузка конфигурации из окружения
├── internal/
│   ├── db/              # инициализация пула соединений с PostgreSQL
│   ├── handlers/        # HTTP-хендлеры по доменам (auth, users, tasks)
│   ├── middlewares/     # проверка аутентификации и роли
│   └── models/          # структуры запросов и ответов
├── utils/               # хеширование, токены, куки, валидация, JSON-ответы
└── schema.sql           # схема базы данных
```

## Модель данных

- `users` — пользователи (логин, ФИО, хеш пароля, флаг администратора)
- `tasks` — задачи (заголовок, описание, статус выполнения)
- `task_users` — связь многие-ко-многим: какие пользователи назначены на задачу
- `sessions` — активные сессии (хеш токена, привязка к пользователю)
